Enforcing business rules before AI agents act

Article created on November 23, 2026 · Source published on November 18, 2026 · Microsoft

On November 18, Microsoft announced the public preview of Agent Controls, an Azure service that evaluates an agent’s actions and content at runtime. The application hosting the agent enforces the decision and can retain a receipt identifying the policies evaluated and their versions. Acceptance testing should confirm that the decision has the intended effect in the business application.

1. Check the rule before the tool call

Microsoft uses Agent Hooks to define intervention points and the Agent Control Specification to structure requests and decisions. Consider an agent handling credit note requests in Odoo Enterprise. Define a rule that allows draft preparation, requires finance approval above the internal threshold and reserves posting for the authorised role. Check that the rule runs before every write call and that Odoo permissions also apply to the agent’s service identity.

2. What changes for Belgian and French companies

An SME can start with one workflow and ask its accounting lead to replay three cases covering an amount below the threshold, an amount above it and an unauthorised user. A mid-market company running several agents can replay the same cases in each environment. IT can then compare the decision, the action actually taken and the record retained. For sensitive cases, check what data is sent to the service evaluating the rule.

3. Underside analysis on outage testing and data minimisation

Simulate a policy engine timeout and verify that the write stays blocked and the case goes to manual review. After recovery, check that retrying creates no duplicate. For a RAG-enabled agent, enforce document permissions during retrieval and send the policy engine only the attributes it needs to decide. Compare a local engine and a cloud service on the same cases, recording where attributes and logs are processed.

4. Link the decision to the business outcome

Retain a case identifier, the policy version, the verdict and the result returned by Odoo. Check that a denial produces no write, an approval produces the expected draft and a manual intervention can be traced to the correct role. Count wrongly permitted actions and wrongly blocked cases before expanding automation.

Before enabling write permissions, have the business owner and IT approve the acceptance cases and recovery procedure.
