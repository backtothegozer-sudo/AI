AWS WorkSpaces for AI agents: identity and audit before Odoo Enterprise

Article created November 17, 2026 · Publication analysed: November 16, 2026 · Source: AWS

AWS has announced new Amazon WorkSpaces capabilities for AI agents: OIDC authentication, on-behalf-of sign-in and session replay retained in an S3 bucket encrypted with customer keys. For Odoo Belgium, Odoo France and Odoo Enterprise, the practical signal is to make identity and execution evidence prerequisites, without mistaking an agent’s desktop for business authorization.

1. The agent’s identity must remain attributable

AWS says agents can now sign in through an OIDC-compatible identity provider in addition to SAML. On-behalf-of sign-in runs an agent with the signed-in user’s identity, permissions and Group Policies. This can reduce the need for overly broad technical accounts, but does not show that every action is appropriate. An organization must still be able to attribute an action to a user, agent, tool, time and business case.

2. Visual evidence does not replace application logs

Session replay turns screenshots into a video paired with a transcript of the agent’s actions; AWS says these artifacts are stored in the customer’s S3 bucket and encrypted with the customer’s keys. That is useful evidence for investigation and review, but it should be reconciled with Odoo logs, API calls, approvals and failures. A video alone does not prove that an invoice, payment or permission change followed the proper path.

3. Define what an agent may do for a person

For an Odoo Enterprise workflow, separate reading, preparation and writing. An agent may look up a status, prepare a draft or open a case; accounting entries, bank-detail changes, price approvals and permission changes should require an application rule and, depending on the risk, human approval. Rights inherited from a user must remain least-privilege: delegation must never become a shortcut to an administrator role.

4. A practical test for Belgian and French organizations

Test an end-to-end scenario with synthetic data: a user delegates a search, the agent prepares a draft, a manager approves or declines it, then the team reconstructs the operation from WorkSpaces and Odoo evidence. Also test access revocation and an unavailable environment. Document data residency, administrator access, video and log retention, and the exit mechanism. These controls are needed to assess a deployment; the AWS announcement alone does not establish GDPR compliance or processing sovereignty.

Recommendation: for every agent acting on behalf of an employee, maintain an « identity, scope, tools, approvals, evidence, revocation » record. It connects technical delegation to operational accountability.
